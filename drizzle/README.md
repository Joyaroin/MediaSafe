# Migrations

Generated by `npm run db:generate`, applied by `npm run db:migrate`, committed as plain
SQL. Read the generated file before committing it — that is the point of generating SQL
rather than pushing a schema diff. Editing it by hand is expected; drizzle-kit hashes
each file when it is *applied*, not when it is written.

The folder is empty apart from its journal, and that is the state issue #38 leaves it
in. This ticket built the pipeline; it did not choose the first thing to send through
it. Better Auth's four tables arrive with issue #42 and MediaSafe's six with build
step 2, in one history, from one tool, in one order.

Two things bind everything that lands here:

- **Expand-contract, forward-only** (`SPEC.md` §3, constraint 7). A column is never
  dropped in the change that stops using it. `squawk` is narrowed to destructive rules
  and fails on a dropped column or table, which is what makes that mechanical rather
  than remembered. Neon Free keeps six hours of history and a restore overwrites the
  branch, so this is the actual protection for the data, not a rollback policy.
- **The whole pending run is one transaction.** Drizzle's migrator opens it — see the
  note at the top of `db/migrate.ts` and the test that holds it true. The consequence
  that bites: **statements Postgres forbids inside a transaction block cannot be used
  here.** `CREATE INDEX CONCURRENTLY` is the one build step 2 will reach for; use the
  plain locking form instead, on a library of 472 titles where the lock is imperceptible.
